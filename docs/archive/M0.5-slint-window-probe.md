# M0.5 三问之二：Slint 窗口属性试验报告

> 试验工程：`experiments/slint-probe/`（独立于根 workspace，Slint 1.18 + winit 后端 + software 渲染器）。
> 运行：`cd experiments/slint-probe && cargo run`（在仓库根）。
> 日期：2026-10-03，Windows 10/11 x64。

## 1. 试验问题

跨端 GUI 工具包（L2 渲染路线，Slint 为最佳候选）能否拿到候选窗必需的窗口属性：

1. **置顶**（always-on-top）
2. **显示时不抢焦点**（show 不夺前台）
3. **点击不激活**（鼠标交互不夺前台）

## 2. 试验设计

两个真实窗口对垒：

- **候选窗**：Slint 窗口（`always-on-top: true`，320×200）；
- **宿主窗口**：原生 Win32 窗口，扮演「正在打字的应用」，通过 `SetForegroundWindow` 取得前台作参照。

判定手段：`GetForegroundWindow` 采样 + 窗口消息级证据（子类化 proc 记录 `WM_ACTIVATE`/`WM_MOUSEACTIVATE`/`WM_SHOWWINDOW`）。

no-activate 手段（候选窗标准手法）：

- 置 `WS_EX_NOACTIVATE` 扩展样式位；
- 子类化 wndproc，对 `WM_MOUSEACTIVATE` 返回 `MA_NOACTIVATE`；
- 显示用 `SW_SHOWNA` 而非 `SW_SHOW`。

## 3. 结果

| 项 | 结论 | 证据 |
|---|---|---|
| T1 置顶 | **PASS** | Slint 原生 `always-on-top` → `WS_EX_TOPMOST` 位真实生效（exstyle=0x40118） |
| T2 基线 | 默认 `show()` **会抢焦点** | Slint 默认行为是激活窗口（预期内，生产中改用 Win32 `SW_SHOWNA` 显示即可） |
| T3 显示不夺前台 | **PASS**（沙箱自动版 + 真机双重确认） | 宿主前台时，候选窗 `SW_HIDE`→`SW_SHOWNA` 循环，前台始终留在宿主 |
| T4 点击不激活 | **PASS**（真机人工验证，2026-10-03） | 用户多次点击候选窗：前台始终留在原程序；「被激活累计」恒为 **0** |
| T5 对照组 | **PASS**（由 T4 反证成立） | 同一会话中用户正常操作其他窗口均正常激活，唯独候选窗永不激活 |

### 真机手动模式结果（manual 模式，交互桌面）

用户在交互桌面操作 `slint-probe.exe manual`（窗口常驻 + shim 开启 + 实时状态）：

- 反复点击候选窗 → 状态恒为「前台在候选窗：否 ✓」，激活累计 **0 次**；
- 切换到其他程序打字 → 置顶候选窗**未打断过一次输入**；
- 有趣的发现：`WS_EX_NOACTIVATE` 位生效时，系统点击候选窗**根本不发 `WM_MOUSEACTIVATE`**
  （「点击命中」计数恒 0）——即系统直接跳过激活询问，位本身已足够；
  wndproc 子类化 shim 降级为兜底（防 librqime…即各 Windows 版本行为差异），保留无害。

## 4. 环境限制说明（已由真机验证解除）

沙箱会话为非交互桌面：`SendInput` 被接受但注入的点击不投递（子类化 proc 全程无
`WM_MOUSEACTIVATE`），自动版 T4/T5 无法在沙箱闭环。
**已通过 manual 手动模式在真机交互桌面补验（见 §3 真机结果），T4/T5 判定 PASS。**

排除过程中确认的事实（记录在案）：

- 仅设 `WS_EX_NOACTIVATE` 位**不足以**阻止 winit/Slint 主动 show 路径的激活，
  `SW_SHOWNA` 显示仍必要；点击路径上则位已足够（系统跳过激活询问）；
- `GetForegroundWindow` 在无第二真实窗口的退化场景下读数不可信，
  试验必须用真实宿主窗口做前台参照（第一轮教训）。

## 5. 对 M0.5 决策门的结论

**Slint 可用（Q2 闭环）。** 具体回答 M0.5 第二问：

- topmost：原生支持，零成本；
- 不抢焦点：`SW_SHOWNA` 显示（对主动 show 路径）+ `WS_EX_NOACTIVATE` 位（对点击路径），
  真机验证点击与打字均不受扰；
- 点击不激活：真机确认位生效后系统直接跳过激活询问；wndproc 子类化
  （`MA_NOACTIVATE`）作为兜底 shim 保留，合计**一层极薄平台层**；
- 各端对应物：Windows = 上述（已验证）；Linux = override-redirect / Wayland layer-shell；
  macOS = `NSPanel`（nonactivating style mask）。均为平台级薄层，不触及 Slint 内部。

→ **L2 路线（跨端 GUI 工具包渲染候选窗）在窗口属性维度无阻断（Windows 已实证）**。
Linux/macOS 对应手段在 M6/M7 时点验证即可。
